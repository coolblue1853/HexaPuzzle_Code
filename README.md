### 1. 프로젝트 개요
 **개발 환경:** Unity (C#)
 **아키텍처:** 모델(Model) / 뷰(View) / 컨트롤러(Controller)의 역할을 분리하여 높은 재사용성과 유지보수성을 확보했습니다.

---

### 2. 개발 환경

* **Unity Version:** 2022.3.62f2
* **언어:** C#
* **대상 플랫폼:** Android

### 3. 프로젝트 구조 및 설계

제공된 코드는 **SOLID 원칙**을 기반으로 인터페이스를 적극 활용하여 각 기능을 분리하고, **의존선 주입**을 통해 모듈 간의 결합도를 낮췄습니다.

#### **핵심 모듈 (Core Logic)**

| 인터페이스/클래스 | 역할 | 상세 내용 |
| :--- | :--- | :--- |
| `IBoard` / `Board` | 게임 보드 모델 및 메인 컨트롤러 | 블록 데이터 관리, 스왑 처리, 연쇄 반응 시작. `Task`/`await`를 활용한 비동기 동작 처리. |
| `IMatchFinder` / `MatchFinder` | 매치 검색 로직 | 직선(Line) 및 클러스터(Cluster) 매칭 조건 검사. |
| `IMatchProcessor` / `MatchProcessor` | 연쇄 반응 감독 | 매치된 블록 제거, 특수 블록 생성/발동, 장애물(잭) 활성화, 중력/리필 재귀적 처리. |
| `IBoardModifier` / `BoardModifier` | 보드 상태 변경 로직 | 중력(Gravity) 적용 및 새 블록 리필(Refill). |
| `IBoardAnalyzer` / `BoardAnalyzer` | 보드 분석 로직 | 이동 가능한 매치 존재 여부(`HasAvailableMoves`) 및 힌트(`GetHint`) 검색. |

#### **시각 및 시스템 모듈 (View & System)**

| 클래스 | 역할 | 상세 내용 |
| :--- | :--- | :--- |
| `GameManager` | 게임 상태 관리 | 남은 이동 횟수, 목표 수집 카운트, 게임 클리어/오버 판정. |
| `HexaGrid` / `HexaCoordinateConverter` | 헥사 좌표계 처리 | Odd-Q 헥사 그리드 좌표 계산, 월드 좌표 변환. |
| `BoardManager` / `BoardViewAnimator` | 시각적 표현 및 애니메이션 | 모델의 변화(스왑, 낙하, 매치)에 맞춰 애니메이션/이펙트 처리. `BlockMover`를 이용한 스무스 이동 구현. |
| `InputManager` | 사용자 입력 처리 | 드래그 방향에 따른 6방향 이웃 블록 스왑 시도. |
| `ObjectPooler` | 오브젝트 풀링 | 블록 및 이펙트 재활용을 통한 런타임 성능 최적화. |

### 4. 필수 및 가산점 구현 상세

#### **4.1. 필수 구현 항목**

1.  **드랍 로직 (Gravity, `BoardModifier`)**
    * 각 열(Q축)을 기준으로 아래(R축 증가 방향)부터 스캔하여 빈 공간이 있을 경우 상위 블록들을 이동시킵니다.
    * 빈 칸이 막힌 구조물(잭 인 더 박스) 위에 있을 경우 해당 열의 중력 계산을 중단합니다.

2.  **매칭 조건 (`MatchFinder`)**
    * **직선 (Line) 매칭:** 육각 타일의 세 가지 직선 방향(0/3 (우상/좌하), 1/4 (우/좌), 2/5 (우하/좌상))으로 3개 이상의 동일 색상 블록 연결 시 매치.
    * **클러스터 (Cluster) 매칭:** 중심 블록을 기준으로 인접한 6방향 이웃 블록 중, 동일 색상 블록이 연속적으로 3개 이상 배치되고 중심 블록을 포함하여 **총 4개 이상**일 경우 매치. (제공된 코드에서는 **중심 블록 포함 총 4개 이상**으로 구현되어 있습니다.)

3.  **장애물: 잭 인 더 박스 (`Board`, `MatchProcessor`, `UIEffectManager`)**
    * `Board.IsObstacleAt`을 통해 일반 블록의 배치 및 스왑/이동을 방지합니다.
    * 인접한 일반 블록이 매치되어 제거될 때(`MatchProcessor` 내부 로직), 주변 잭 장애물을 활성화(`OnJackActivated` 이벤트)합니다.
    * `UIEffectManager`에서 활성화된 잭의 폭발 이펙트 출력 후, 잭이 목표 지점(Goal)으로 날아가는 애니메이션을 연출하고 `GameManager`에 목표 수집을 알립니다.

4.  **클리어 조건 (`GameManager`)**
    * `MapData`에 설정된 목표 수(`goalCount`) 만큼 잭을 수집(`CollectGoalObject`)하면 **게임 클리어**됩니다.
    * 남은 이동 횟수(`moveLeftCount`)가 0이 되고 진행 중인 애니메이션이 없으면 **게임 오버**됩니다.

5.  **특수 블록 생성 및 기능 (`MatchProcessor`)**
    * **생성:** 직선 4개 이상 매치 시, 스왑된 블록 중 하나(혹은 중앙 블록)의 위치에 해당 방향성을 가진 **라인 삭제 (`BlockType.Line`)** 특수 블록을 생성합니다.
    * **기능 (연쇄 발동):** 특수 블럭이 매치 그룹에 포함되거나 다른 특수 블록에 의해 폭파되면, 해당 블록이 가진 방향의 **보드 끝까지** 모든 블록을 파괴합니다.
    * **연쇄 폭발 처리:** 파괴된 블록 중 다른 특수 블록이 있다면, `MatchProcessor`의 `activationQueue`에 추가되어 연쇄적으로 폭발하도록 처리했습니다.

6.  **인게임 연출 개선 및 안정성 확보**
    * **비동기 처리:** `TrySwapBlocksAsync`, `ProcessMatchesAsync`에서 `Task`와 `TaskCompletionSource`를 사용하여 애니메이션(스왑, 낙하, 리필, 특수 블록 생성)의 완료를 기다린 후 다음 로직(모델 업데이트)을 진행하는 안정적인 비동기 게임 루프를 구현했습니다.
    * **힌트 시스템:** 5초간 입력이 없을 시, `BoardAnalyzer`를 통해 이동 가능한 힌트 블록을 찾아 `HintVisualizer`로 반짝이는 효과를 표시합니다.
    * **셔플 시스템:** 이동 가능한 매치가 전혀 없을 경우(교착 상태), 보드 전체를 무작위로 다시 생성하고 매치가 생기지 않도록 검증 후, 플레이어에게 새로운 보드를 애니메이션과 함께 제공합니다.
